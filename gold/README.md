# Gold — Yoru 认可过的自己的成片

这里是**正样本层**：Yoru 在真实交付里用过并认可的完整成片，一族一个目录。
它的优先级高于库里其它一切——做同类东西时，直接以这里的条目为母版，只换内容，
**禁止重新设计**。

库里其它层（`shots/`、`layouts/`）收的全是别人的镜头；这一层收的是她自己的作品。
一个 agent 做"她以前做过的东西"时，答案不在任何规则里，在这里。

| （空位）| 图 + 文 | — | 作品介绍卡、截图配说明——**尚无母版** |

**同族判定：内容结构相同 + 用途相同才算同族。** 问题卡和作品介绍卡不是同族，
即使都是 4 秒采访插卡。两族都匹配时，按各自 README 的用途描述选，并在交付说明里写选择理由。

## 空位规则

任务落在空位类型（库里没有同族母版）时：

- 允许借现有 gold 条目的 palette、入退场节奏包络、编码参数；
- **构图（版式、字号、图文比例、装饰）没有依据——方案必须作为 proposal 交回
  Yoru 拍板，不许当成品交付**；每个自定值标 ASSUMPTION；
- Yoru 认可后的成片就是该空位的第一个母版，当场归档入库。

## 每个条目长这样

```
gold/<family-slug>/
├── README.md      # 这是什么、什么时候直接用我、参数表（每个元素第几帧进/出、缓动）、
│                  # 验证记录、来源（哪次交付、哪个会话、源码是原生还是恢复的）
├── render_*.py    # 能原样重跑出成片的源码，自包含优先（.tsx 同理）
└── stills/        # 关键帧抽帧图：入场中段、定格、退场——云端 agent 看不了 MP4，靠这些
```

MP4 本体不进本仓库（云端 agent 反正看不了视频）。

## 规矩

- **门槛**：只收 Yoru 在真实交付里用过并认可的。做着玩的、没用过的不算。
- **审核期只交 MP4**：Remotion / motion deliverable 在 Yoru 明确确认前，只发送或提供 MP4 供审核；不要主动通过邮箱发送源码 ZIP、JS/TS/TSX、bundle 或其它源码附件。源码留在当前工作环境，等待确认。
- **确认词触发归档**：Yoru 明确说“通过 / OK / 可以了”或其它等价确认时，视为该版本已批准；立即把对应源码按本 README 规范整理、去客户化并归档到 `gold/`。已有同族则按同族规则处理；没有同族则按上面的「空位规则」新建 family。
- **内容参数没给就用条目默认值**，并在交付说明里指出；不许因为缺参数就增删或隐藏
  版式元素（底部说明行、横线等都是版式的一部分，不是可选项）。
- **环境**：条目代码需要 Pillow + FFmpeg；字体默认 Linux 容器路径，其他平台用
  `--serif-font` 等参数覆盖（Windows 用户字体目录常有同款 NotoSerifCJKsc/NotoSansCJKsc）。
- **公开库必须去客户化**：本仓库是公开的。条目进来时，代码里嵌的真实交付文案、
  客户名、项目名全部换成中性占位默认值，抽帧图用占位文案重渲。真实文案与交付
  MP4 只留在本地/私有侧。这条与 `evaluation/benchmark-plan.md` 的 fixtures 规则同源。
- **冻结**：条目内容不改，要改就开新条目；验证记录可以追加。
- **来源必录**：交付日期、来源会话、源码是原生存档还是事后恢复。
- **定稿即归档**：新东西被 Yoru 拍板的当场，就把源码入库，别等窗口凉了。
  question-card 族的源码曾经差点永远丢失——原会话里代码没存盘，事后靠考古才救回来。
